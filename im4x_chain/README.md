# im4x-chain в REAPER

Два действия: выделяете айтемы, запускаете — активный тейк каждого айтема (WAV/FLAC)
проходит цепочку `im4x-chain` в фоне, REAPER при этом не замирает. Работает на macOS,
Windows и Linux.

| Скрипт | Файл на диске | Проект |
|---|---|---|
| `im4x_chain_overwrite.lua` | исходный файл заменяется результатом (после подтверждения) | все айтемы с этим файлом перезагружаются, пики перестраиваются |
| `im4x_chain_take.lua` | результат пишется рядом: `<имя>_rx.<ext>` (`_rx2`, … если занято) | в айтем добавляется новый активный тейк; исходный тейк остаётся (переключение — `T`) |

Общий движок — `im4x_chain_core.lua`, он должен лежать в той же папке.

## Окно прогресса

- файлы обрабатываются по два одновременно (`[process] jobs` в `config.toml` CLI; так быстрее
  примерно на четверть), у каждого файла в работе своя строка:
- имя файла и номер («Файл 2 из 3»), текущий этап («Этап 6 из 11: Spectral De-noise»);
- полоса по файлу: этапы взвешены по их обычной длительности, внутри этапа полоса
  движется по оценке времени (≈ 0.02 с на секунду звука) и не уходит дальше этапа;
- при нескольких файлах — полоса «Всего» (по длине звука) и сколько файлов готово;
- текст рисуется в разрешении экрана (Retina и HiDPI на Windows);
- **Esc** или закрытие окна — отмена. Процессы убиваются до подмены файлов, поэтому файлы
  в работе не меняются; уже обработанные файлы остаются обработанными.

Этапы видны, если CLI поддерживает `--progress-file`. Со старым CLI окно показывает только
полосу по оценке времени.

## Установка

Проще всего — установщик из архива репозитория (`install.cmd` на Windows,
`install.command` на macOS): он ставит CLI и сам копирует эту папку в REAPER, остаётся
шаг 3. Вручную:

1. Установите CLI `im4x-chain` (см. основной README репозитория); на Windows он
   ставится в `%USERPROFILE%\.local\bin\im4x-chain.exe`.
2. Скопируйте папку `im4x_chain` в папку скриптов REAPER:
   - macOS: `~/Library/Application Support/REAPER/Scripts/`
   - Windows: `%APPDATA%\REAPER\Scripts\`
   - Linux: `~/.config/REAPER/Scripts/`
3. **Actions → Show action list → New action → Load ReaScript…** — выберите
   `im4x_chain_overwrite.lua` и `im4x_chain_take.lua`.

CLI ищется так: путь из ExtState, переменная `IM4X_CHAIN_CLI`, затем
- macOS/Linux: `~/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin`, `command -v` в login-shell;
- Windows: `%USERPROFILE%\.local\bin\im4x-chain.exe`, затем `where im4x-chain`.

Свой путь (например, CLI из клона репозитория) задаётся один раз из консоли ReaScript:

```lua
reaper.SetExtState("im4x_chain", "cli", "/Users/me/im4x-chain/.venv/bin/im4x-chain", true)
-- Windows:
reaper.SetExtState("im4x_chain", "cli", [[C:\Users\me\im4x-chain\.venv\Scripts\im4x-chain.exe]], true)
```

## Настройки цепочки

Скрипты запускают CLI с его настройками: значения по умолчанию и файл
`config.toml` (macOS/Linux: `~/.config/im4x-chain/config.toml`, Windows:
`%APPDATA%\im4x-chain\config.toml`). Изменения в файле действуют со следующего запуска,
переустанавливать ничего не нужно. Создать файл-шаблон: `im4x-chain config --init`; подробности —
в основном README репозитория (раздел «Настройки»).

## Как это устроено

CLI запускается в фоне через небольшой скрипт-обёртку во временной папке: на macOS и Linux —
`/bin/sh`, на Windows — скрытый PowerShell (`powershell.exe -WindowStyle Hidden`, без окна
консоли, UTF-8 для путей и вывода). Обёртка пишет PID, лог и код выхода; CLI пишет события
прогресса (`--progress-file`), окно читает их раз в кадр. Отмена убивает всё дерево
процессов (`kill` по дереву на macOS/Linux, `taskkill /T /F` на Windows).

## Что важно знать

- Файл, который играют несколько айтемов, обрабатывается один раз. При перезаписи меняются
  и невыделенные айтемы с этим файлом — окно подтверждения говорит, сколько их.
- На время обработки айтемы с этим файлом переводятся в offline (при перезаписи). На Windows
  это обязательно: занятый файл заменить нельзя. Если тот же файл открыт в другой вкладке
  проекта или в другой программе, перезапись на Windows завершится ошибкой, файл не изменится.
- Новый тейк наследует offset, playrate, pitch, громкость, панораму и режим каналов
  исходного тейка; FX и огибающие тейка не копируются. Если исходный тейк был секцией
  или реверсом, новый тейк играет файл целиком с тем же offset.
- Добавление тейков отменяется через Undo (одна точка на файл); перезапись файла — нет.
- Windows-часть проверена только на имитации (сгенерированные команды и скрипт PowerShell),
  в REAPER на Windows её ещё не запускали.
