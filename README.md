# im4x-chain — цепочка обработки озвучки без приложения RX

Цепочка на Python (`numpy` + `scipy`); приложение RX для неё не запускается. Три этапа —
это плагины RX 12 (VST3), которые цепочка открывает сама через `pedalboard` (Spectral
De-noise и Mouth De-click — с настройками из Module Chain пользователя). Остальное — свой код:

```
EQ (свой, срез низа по голосу) → De-plosive (плагин RX, только где есть плозивы)
  → Mouth De-click (плагин RX) → Spectral De-noise (плагин RX)
  → Leveler (свой) → компрессор (своя модель SSL X-Comp) → Loudness Control (свой)
```

Порядок отличается от Module Chain RX в двух местах:

- **щелчки до шума**: иначе щелчки попадают в слепок шума, а спектральное шумоподавление
  размазывает их, и de-click потом хуже их находит (так советует и iZotope);
- **Loudness Control последним**: компрессор после него снимал пики, и итог был тише цели
  на 1.1–1.7 LU (у RX то же самое — −25.2…−25.8 LUFS при цели −24). Теперь цель и потолок
  true peak выполняются точно: −24.00 LUFS, true peak не выше −3 dBTP.

## Установка

Заранее нужен установленный iZotope RX 12 (плагины VST3 `RX 12 De-plosive`,
`RX 12 Mouth De-click`, `RX 12 Spectral De-noise`). Само приложение RX не запускается.

macOS (нужен [Homebrew](https://brew.sh)):

```sh
brew install uv gh
gh auth login
uv tool install git+https://github.com/im4xxx/im4x-chain
```

Windows (после первой команды открыть новый терминал):

```sh
winget install astral-sh.uv Git.Git
uv tool install git+https://github.com/im4xxx/im4x-chain
```

Всё: команда `im4x-chain` доступна из любой папки. Python и зависимости (numpy, scipy, numba,
pedalboard, soundfile) `uv` ставит сам.

- Репозиторий закрытый, поэтому нужен вход в GitHub: на macOS — `gh auth login` (выбрать
  HTTPS и разрешить вход для Git), на Windows окно входа откроется само.
- Команда `im4x-chain` не находится — выполнить `uv tool update-shell` и открыть новый терминал.
- Плагины RX ищутся в `/Library/Audio/Plug-Ins/VST3` (macOS) и
  `C:\Program Files\Common Files\VST3` (Windows), другая папка — переменная
  `IZOTOPE_RX_VST3_DIR`. Без плагинов работают EQ, Leveler, компрессор и Loudness
  (`--no-deplosive --no-declick --no-denoise`).
- Обновить: `uv tool upgrade im4x-chain`. Удалить: `uv tool uninstall im4x-chain`.

## Запуск

Командная строка:

```sh
im4x-chain process ~/Audio/ep01 -o ~/Audio/ep01-out
im4x-chain process file.flac --target -16 --eq hp:60 --eq peak:3500:+1.5:1.2
im4x-chain measure ~/Audio/ep01-out
```

Без `-o` файлы перезаписываются на месте (через временный файл и атомарную замену).
`--no-eq`, `--no-deplosive`, `--no-denoise`, `--no-declick`, `--no-leveler`, `--no-loudness`, `--no-comp` отключают стадии; параметры
компрессора — `--comp-threshold`, `--comp-ratio`, `--comp-attack`, `--comp-release`,
`--comp-knee`, `--comp-makeup`; Reduction шумоподавления — `--reduction` (по умолчанию из цепочки, 16 dB); `--json` печатает полный отчёт;
`--progress-file PATH` пишет прогресс строками JSON (`begin`, `stage`, `done`) — его читают
ReaScript-скрипты.

Файлы: WAV остаётся WAV того же формата; FLAC пишется сразу во FLAC (libsndfile, уровень
сжатия 5, как `flac -5`) той же разрядности, теги и обложка не переносятся. Промежуточного WAV
нет. 16 бит — с TPDF-дизером; в отрезках по 10 мс, которые и так округлились бы в ноль,
дизер выключен, чтобы цифровая тишина осталась тишиной.

Скорость: часовой моно-файл 48 kHz — 41–51 с на всю цепочку вместе с чтением, записью FLAC
и замерами; из них шумоподавление 14–17 с (подбор кривой ~1 с), De-plosive ~7 с, de-click
~3.5 с, высота голоса ~2 с, EQ ~2 с, Loudness Control 1–6 с (Module Chain в RX на тех же
файлах — 2.1–3.2 мин на файл).
EQ и K-взвешивание считаются кусками в потоках по ядрам (`chunks.py`, у каждого куска 2 с
разгона фильтра — результат совпадает с одним проходом бит в бит); Loudness Control меряет
громкость и true peak сигнала один раз и пересчитывает их для каждого шага усиления.
True peak считается своим полифазным ядром на `numba` (тот же фильтр, что у
`scipy.signal.resample_poly`, значения совпадают до 1e-15, в 9 раз быстрее).

в [`reaper/README.md`](reaper/README.md).

Вторая, независимая версия тех же двух действий с полосой прогресса и отменой по Esc — в

## EQ

Полосы — короткие строки (`--eq`):

| Полоса | Что делает |
|---|---|
| `hp:60[:order]` | срез низа (high-pass), Butterworth, по умолчанию порядок 4 = 24 dB/окт, −3 dB на частоте |
| `lp:16000[:order]` | срез верха (low-pass) |
| `peak:3000:+2[:Q]` | колокол, Q по умолчанию 1.0 |
| `lowshelf:200:-2[:Q]`, `highshelf:8000:+1.5[:Q]` | полки, Q по умолчанию 0.707 |

По умолчанию — срез низа по голосу и `lp:18000:8` (срез верха 18 kHz 48 dB/окт, как Band 8
пункта EQ в Module Chain RX). Срез низа (24 dB/окт) = 0.55 × нижняя высота голоса (5-й
перцентиль основного тона), от 70 до 120 Hz с шагом 5 Hz: низкий мужской голос остаётся на
70 Hz, как в цепочке RX, высокий женский или детский получает до 120 Hz — рокот, гул и
энергия плозивов уходят, а основной тон не задет (на нём срез меньше −0.1 dB). Высота тона —
автокорреляция кадров по 64 мс на 16 kHz (громкие 40 % кадров, не больше 20 000), с
поправкой на окно (Boersma) и проверкой субгармоник; ~2 с на час. Найденное — в
`eq.voice` отчёта. На тестовых записях (женские голоса, медиана 270–500 Hz) срез 110–120 Hz.
Если голос не найден, срез 70 Hz. Срезы выше четверти частоты дискретизации считаются на удвоенной
частоте: цифровой Butterworth у Найквиста намного круче своего наклона (18 kHz 48 dB/окт
при 48 kHz дал бы −18 dB на 19 kHz), а так форма близка к аналоговой, как у EQ в RX
(−3 dB на 18 kHz, −6 на 19, −10 на 20).
Фильтры каузальные (минимальная фаза, как аналоговый EQ), peak/shelf — биквады RBJ.
Список `--eq` заменяет полосы по умолчанию целиком (и отключает подбор по голосу), так что
срезы нужно указать снова, если они нужны вместе с другими полосами.

## Spectral De-noise и Mouth De-click (плагины RX)

Нужны установленные `RX 12 Spectral De-noise.vst3` и `RX 12 Mouth De-click.vst3` в
папке VST3 (см. «Установка»). Настройки пунктов Module Chain лежат в
`src/im4x_chain/data/rx_chain_plugins.json`.

Состояние плагина — JUCE-обёртка «VC2!», внутри zlib-JSON; у Spectral De-noise в нём
двоичный блок с профилем шума и кривой подавления. Цепочка не нажимает Learn, а пишет
профиль сама: спектр участка шума (тот же расчёт, что у RX: рендер с нашим и с RX-овским
блоком совпадает бит в бит).

Для каждого файла:

1. слепок шума. Фон комнаты в конце записи (обычно между финальными хлопками и после них):
   самый длинный тихий отрезок (уровень < пол + 6 dB) в последних 30 с, не короче 3 с, берётся
   целиком — решает только уровень, поэтому гул или тон в фоне попадает в слепок. Отдельно
   берутся ~4 с пауз из самой записи (`noise_finder`): фон в паузах и в хвосте бывает разным
   (у одного файла паузы на низу громче хвоста на 8–9 dB). Профиль — большее из двух
   спектров на каждой частоте, так что давится гул и из хвоста, и из пауз. Нет хвоста —
   лучшие участки шума целиком (без обрезки до 4 с), склеенные до ~2 с с кроссфейдом 10 мс;
2. подбор кривой идёт по шуму «как до EQ» (к слепку прибавляется то, что срезал EQ), хотя
   плагин получает слепок обработанного сигнала. Так подавление совпадает с RX, где
   Spectral De-noise стоит перед EQ: там жёлтая кривая видит полный низ, подавление на низу
   глубже, а EQ потом срезает низ ещё раз. Без этого низ в паузах выходил на 6–8 dB громче.
   Сам подбор: жёлтая кривая считается так же, как её рисует RX, — «спектр слепка минус
   подавление на частоте» (сверено с кривыми из памяти RX: совпадение ~1 dB). Каждая из
   189 точек кривой подавления сдвигается к цели: не выше −122 dB и не выше чем на 5 dB над
   самыми тихими полосами шума (p5). Кривая только добавляет к Reduction цепочки (16 dB),
   до 40 dB всего: полосы, которые и с базовым подавлением тише цели (обычно верха), так и
   остаются тише — их не «поднимают» до порога, и в разброс они не засчитываются. Критерий тот же, что у пакетной
   обработки в RX: максимум < −120 dB, разброс p95−p5 ≤ 6 dB, горбы ≤ 6 dB в полосе
   60 Hz–16 kHz. Если не вышло — пробуются следующие участки шума (до 3), берётся лучший;
3. рендер всего файла в нескольких процессах: куски по 60 с с запасом 2 с по краям, плагин
   на каждом куске сбрасывается (задержка компенсируется), цифровая тишина пропускается.
   Кусочный рендер совпадает с рендером целиком до −76 dB.

В отчёте `denoise`: `residual_max_db`, `residual_spread_db`, `residual_bump_db`,
`passed`, подавление на 50/200/1k/5k/15k Hz и `measured_output_max_db` — реальный спектр
выхода плагина на слепке. Он выше расчётной жёлтой кривой на 5–13 dB (подавление в
плагине неидеально, и его выход на коротком слепке шумнее модели); RX показывает именно
расчётную кривую, поэтому критерий считается по ней.

Качество (Quality) — Extreme, как в цепочке RX. Adv.+Extr. рендерит в ~4.6 раза медленнее при
той же глубине подавления.

Mouth De-click — плагин с настройками цепочки (Sensitivity 4.5, Frequency skew 2.5,
Click widening 0), рендер тем же способом.

## De-plosive (плагин RX, по необходимости)

`RX 12 De-plosive.vst3` (Sensitivity 5, Strength 5), сразу после EQ. Верхняя частота
ремонта (Frequency limit) — ниже голоса: 0.8 × нижний основной тон (5-й перцентиль), 60–200 Hz
с шагом 5 Hz, в отчёте `deplosive.settings` и `voice_f0_p5_hz`. С плагиновыми 200 Hz мужской
голос (основной тон 100–140 Hz) терял основной тон: плагин принимал низ гласных за плозивы
(в среднем −2 dB на 90–200 Hz, на отдельных словах заметно больше). На мужском голосе с
основным тоном от 115 Hz граница 90 Hz: 90–110 Hz −0.4 dB, выше — без изменений, ниже 70 Hz
плозивы по-прежнему снимаются (−11 dB). У высокого женского голоса (основной тон от 200 Hz)
граница 160 Hz: снимается только то, что ниже тона, полоса от 140 Hz не меняется.
Настройки пишутся прямо в состояние плагина: параметры, заданные через `pedalboard`, в
сохранённое состояние не попадают (до исправления плагин всегда работал на 200 Hz).

Его нет в Module Chain, поэтому он работает только там, где нужен: плагин рендерится на каждом файле, и его результат остаётся, только если он убрал
плозивы — места, где низ (< 250 Hz, кадры по 10 мс) упал больше чем на 10 dB, не меньше 20
на час записи (и не меньше 3). В отчёте `deplosive.applied`, число найденных плозивов и
примеры по времени. На тестовых записях: у Ваниллы 61 плозив (включён), у остальных 0–7, и
это в основном хлопки в конце записи (не включён). `--no-deplosive` отключает этап.

## Leveler

Аналог RX Leveler; параметры те же (Target, Responsiveness, Preserve, Ess Reduction),
значения по умолчанию: −24, 3.3, **60 %**, 4 dB. В цепочке пользователя Preserve 65 %; 60 %
выбрано, чтобы чуть уменьшить динамический диапазон (см. «Плотность динамики» ниже).

- Громкость K-взвешенная, по кадрам 10 мс, считается только по речи — паузы не тянут
  уровень.
- Речь делится на фразы (паузы ≥ 0.25 с). Внутри фразы усиление следует громкости
  медленно (гауссово окно σ = max(0.5, 6 / Responsiveness) с, не заходит в соседние фразы),
  поэтому слоги и интонация не сплющиваются.
- Сохраняется Preserve % отклонения фразы от среднего уровня речи, остальное выравнивается.
- Смена усиления между фразами происходит в паузе, а не на словах.
- Де-эссер работает только выше 4.5 kHz (разделение полос с точной реконструкцией), RX же
  опускает весь сигнал на «с».

Сравнение с RX (после нормализации к −24, разброс громкости фраз, dB; меньше — ровнее):

| Клип | Вход | RX | Свой |
|---|---|---|---|
| Коконат, 3 мин | 2.87 | 1.92 | **1.71** |
| Сигурэ, 3 мин | 0.74 | 1.07 | **0.54** |
| short0 | — | **1.15** | 1.79 |

## Loudness Control

Точная интегральная громкость по BS.1770-4 под потолком true peak (по умолчанию −24 LUFS,
−3 dBTP). Измеритель сверен с эталонным синусом 997 Hz (−3.01 LUFS моно).

1. Если пики позволяют — просто усиление, результат ровно в цель.
2. Иначе — мягкий компрессор (3:1, колено 6 dB) плюс true-peak лимитер с ограниченной
   глубиной: порог компрессора подбирается бисекцией так, чтобы лимитер срезал не больше
   бюджета (3 dB). Если цель не достигается — бюджет и ratio поднимаются ступенями
   (3:1/3 dB → 3:1/5 → 5:1/5 → 5:1/8).
3. Дополнительное усиление (makeup) идёт только на речь; в паузах оно спадает за 40 мс,
   поэтому фон в паузах не поднимается.
4. Если цель недостижима без искажений, результат честно ниже цели и в отчёте
   `reached: false` и фактический `out_lufs`.

Сравнение с RX на 3-минутных клипах:

| Цель | Версия | Итог | Рост шума в паузах | SNR |
|---|---|---|---|---|
| −16 | RX | −14.9…−16.6 | — | — |
| −16 | своя | ровно −16.00, TP ≤ −3.0 | 0…1.9 dB | 27.6–32 |
| −12 | RX | −10.3…−11.1 (перелёт) | 14–23 dB | 13–16 |
| −12 | своя | −12.64…−12.71, `reached: false` | 1.9–9.9 dB | 20–22 |

## Компрессор (модель SSL X-Comp)

Последний пункт цепочки RX — AU-плагин SSL Native X-Comp v6 (состояние A: порог −10.7 dBFS,
4:1, атака 0.5 мс, восстановление 199.64 мс, колено 19.69 dB, makeup 0, side-chain фильтры
выключены). Модель снята с самого плагина, запущенного без RX через `pedalboard`:

- детектор пиковый (синус и меандр с одинаковым пиком сжимаются одинаково): однополюсный
  фильтр по `|x|` в линейной амплитуде с раздельными атакой и восстановлением, постоянные
  времени 0.95 × attack и 1.0 × release;
- статическая кривая: квадратичное мягкое колено шириной knee с центром на пороге, выше —
  ровно ratio;
- стерео — общий детектор по громкому каналу, усиление одинаковое на оба канала;
- задержки нет, усиление ≤ 0 dB, поэтому пики не растут и потолок true peak сохраняется.

Расхождение с плагином: на речи −24 LUFS не больше 0.03 dB по усилению (остаток −54 dB);
на других настройках (порог −18…−25, ratio 2–10, атака 0.5–10 мс, восстановление
50–600 мс) — не больше 0.11 dB. Детектор скомпилирован `numba`: 3 минуты моно — ~0.05 с.

Компрессор стоит перед Loudness Control (в RX — после него): он снимает пики, а Loudness
Control затем точно выводит громкость в цель и true peak под потолок. Раньше, со своим
компрессором последним, итог был тише цели на 1.1–1.7 LU при −24 и ещё сильнее при −16.

### Плотность динамики

Настройки X-Comp из цепочки (−10.7 dBFS, 4:1) после Leveler почти не работают: порог выше
речи, компрессор срабатывает на 3–7 % пиков. По умолчанию теперь порог **−20 dBFS, 3:1,
атака 0.1 мс, восстановление 120 мс, колено 8 dB** (сжимаются громкие слоги) и Leveler
**Preserve 60 %** (фразы чуть ближе по громкости). Сравнение на 6 тестовых файлах, итог везде
−24.00 LUFS (замерено с Preserve 45 %; 60 % — между строками «только компрессор» и «оба»):

| Вариант | LRA, LU | разброс слогов (0.4 с, p10–p95), dB |
|---|---|---|
| настройки цепочки RX (65 %, −10.7 dBFS 4:1) | 11.5–16.6 | 13.5–16.7 |
| лимитер вместо компрессора (пики 15 dB над громкостью) | 12.1–16.4 | 14.5–17.0 |
| только компрессор −20 dBFS 3:1 | −1…−1.6 | −1.2…−1.5 |

Атака — минимальная у X-Comp, 0.1 мс. С атакой 5 мс начало слова проходило несжатым, а
остальное слово сжималось, и после подъёма громкости начала торчали: 1.1–8.2 раза в минуту
пик 5 мс выше уровня окружающих 300 мс речи на 15 dB и больше. С 0.1 мс — 0–1.5 раза в
минуту, а LRA ещё на 0.3–1.5 LU меньше; пики ниже, и Loudness Control на всех тестовых
файлах обходится простым усилением, без лимитера.

Лимитер вместо компрессора диапазон не сужает: он срезает только пики (на 5 dB, местами до
12 dB на криках), а разница громкости фраз и слогов остаётся. Вернуть настройки цепочки:
`--preserve 65 --comp-threshold -10.7 --comp-ratio 4 --comp-attack 0.5 --comp-release 199.64
--comp-knee 19.69`.
